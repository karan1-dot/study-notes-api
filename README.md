# Study Notes API

A lightweight REST API for storing and searching study notes, with keyword
relevance search powered by TF-IDF (a foundational NLP technique).

## What this project demonstrates
- **SQL / DBMS**: schema design, CRUD operations against a SQLite database
- **API design**: RESTful endpoints (POST/GET/DELETE) built with FastAPI
- **Applied AI/ML**: TF-IDF vectorization + cosine similarity for search ranking

## Project structure
```
study_notes_api/
├── app/
│   ├── __init__.py
│   ├── main.py        # FastAPI app and route definitions
│   ├── database.py     # SQLite connection + schema setup
│   ├── models.py        # Pydantic request/response schemas
│   └── search.py         # TF-IDF search logic
├── requirements.txt
└── README.md
```

## How to run it

1. **Install dependencies** (from inside the `study_notes_api` folder):
   ```bash
   pip install -r requirements.txt
   ```

2. **Start the server:**
   ```bash
   uvicorn app.main:app --reload
   ```

3. **Open the interactive docs** in your browser:
   ```
   http://127.0.0.1:8000/docs
   ```
   This is auto-generated by FastAPI — you can create, list, delete, and
   search notes directly from this page without needing Postman.

## Example usage (curl)

**Create a note:**
```bash
curl -X POST http://127.0.0.1:8000/notes \
  -H "Content-Type: application/json" \
  -d '{"title":"Normalization","content":"1NF, 2NF, 3NF explained","tags":"dbms"}'
```

**List all notes:**
```bash
curl http://127.0.0.1:8000/notes
```

**Search notes:**
```bash
curl "http://127.0.0.1:8000/search?q=normalization"
```

**Delete a note:**
```bash
curl -X DELETE http://127.0.0.1:8000/notes/1
```

## How the search works (for interview explanation)

Instead of a plain `LIKE '%keyword%'` SQL match, this uses **TF-IDF**
(Term Frequency–Inverse Document Frequency), implemented from scratch in
`search.py` using only Python's standard library (no scikit-learn):

1. **Tokenize**: split each note's text into lowercase words, removing
   common stop words (the, is, and, etc.).
2. **Term Frequency (TF)**: how often each word appears in a given note,
   as a fraction of that note's total word count.
3. **Inverse Document Frequency (IDF)**: words that appear in many notes
   are less informative (low weight); rare, distinctive words get a
   higher weight.
4. **TF-IDF score** = TF × IDF for each word, giving every note a vector
   of weighted word scores.
5. **Cosine similarity** measures how close the query's vector is to each
   note's vector — this becomes the relevance score.
6. Results are sorted by score, highest first.

This means a search for "gradient descent" ranks a note that's genuinely
about gradient descent above one that just mentions it once in passing —
which a simple keyword match cannot do.

Building this by hand (rather than calling `scikit-learn`) means you can
explain every line of the math in an interview, not just "I called a
library function."
